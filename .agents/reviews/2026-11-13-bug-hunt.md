# zujson bug hunt, 2026-11-13

Commit `825f259`. Hunters: 3 on Fable 5.2, run one at a time, none shown
another's report. Their slices: (1) the R layer, (2) the decoder (`zu_parse.c`,
`zu_cond.c`), (3) the emitter (`zu_write.c`) and native ownership across
`src/`. Coordinator on Opus 5.5. Built here: R 4.6.2, x86_64 build on macOS;
an ASan+UBSan build (hunters 2 and 3); gctorture.

Unverified:
- arm64, where `long double` is `double` (this bears on #46) and the cast in
  `zu_df_arg()` saturates;
- Windows paths and code pages (#50);
- a build without long vectors;
- a natural R allocation failure inside `zu_own()` (#52, shown by fault
  injection only);
- the `INT_MAX` guards in `zu_mkchar()` and `zujson_write()` at ±1 (they need
  more than 8 GB);
- R older than 4.3.

Probe scripts are in `2026-11-13-bug-hunt-probes/`. They refer to the
scratch root as `W`; `verify/` holds the coordinator's re-runs.

## 1. Refuse POSIXlt as a data frame column and in json_write_ndjson() — #40, high, reproduced
- Where: [zu_write.c:315-328](https://github.com/pedrobtz/zujson/blob/825f259/src/zu_write.c#L315-L328), [zu_write.c:502](https://github.com/pedrobtz/zujson/blob/825f259/src/zu_write.c#L502); the guard at [:390](https://github.com/pedrobtz/zujson/blob/825f259/src/zu_write.c#L386-L392)
- Trigger: an 11-row frame with a POSIXlt column writes row *i* as field *i* (`"t":[0,1,...,10]`). `json_write_ndjson(as.POSIXlt(...))` writes 11 records.
- Cause: the POSIXlt guard is only on `zu_from_sexp()`. Neither the data frame plan nor the NDJSON loop reaches it.
- Fix: one guard, called from every entry point.
- Family: 3. Siblings checked: a list element and a list column are refused (correct); a direct column and NDJSON top level are not.
- Test the suite lacked: POSIXlt through every writer entry point.
- Found by hunters 1 and 3.

## 2. POSIXct just below midnight is written with hour 24 — #41, high, reproduced
- Where: [zu_write.c:163-168](https://github.com/pedrobtz/zujson/blob/825f259/src/zu_write.c#L163-L168)
- Trigger: `json_write(structure(-1e-12, class = c("POSIXct","POSIXt")))` gives `"1969-12-31T24:00:00Z"`, and so does the epoch plus `(0.3 - 0.1 - 0.2)`.
- Cause: `secs - floor(secs/86400) * 86400` rounds to `86400.0`.
- Fix: floor the seconds first, then split into days in integers.
- Family: none (see Cross-cutting). Siblings checked: `86400 - 1e-11` and `-86400 - 1e-11` give 23:59:59 (correct); the window is about `(-7.3e-12, 0)`.
- Test the suite lacked: values just below each day boundary, compared with `format(floor(x))`.

## 3. Fail instead of writing `<xx>` when a string cannot be translated to UTF-8 — #42, medium, reproduced
- Where: [zu_parse.c:805](https://github.com/pedrobtz/zujson/blob/825f259/src/zu_parse.c#L803-L807), `:845`, `:932`; [zu_write.c:101](https://github.com/pedrobtz/zujson/blob/825f259/src/zu_write.c#L101)
- Trigger: under `LC_ALL=C`, an unmarked `café` parses as `caf<c3><a9>` and is written as that. Invalid UTF-8 (`'["\xe9"]'`) parses as `"<e9>"`, and `json_validate()` says `TRUE`. In any locale, latin1 `"\x81\x8d"` is written as `"<81><8d>"`.
- Cause: `Rf_translateCharUTF8()` substitutes rather than fails.
- Fix: a checked translation and a classed error; or decide, in §5, to read unmarked valid UTF-8 as UTF-8.
- Family: 4. Siblings checked: keys, factor levels, NDJSON both ways, `json_validate()`: all affected. The raw and file routes are correct.
- Test the suite lacked: the hostile-session test (#32).
- Found by hunters 1, 2 and 3.

## 4. Refuse classed objects with the wrong storage type instead of leaking a bare error — #43, medium, reproduced
- Where: [zu_write.c:189-211](https://github.com/pedrobtz/zujson/blob/825f259/src/zu_write.c#L189-L211), `:227`, [:296-328](https://github.com/pedrobtz/zujson/blob/825f259/src/zu_write.c#L296-L328); `Rf_error` at `:454` and `:528`
- Trigger: `json_write(structure(NA, class = "Date"))`; a factor with integer levels; `structure(list(a = NULL), class = "data.frame")`; an atomic vector classed `data.frame`. Each raises a bare `simpleError`.
- Cause: the kind is chosen by class, and the storage type is never checked.
- Fix: check the storage type per class; turn the two `Rf_error`s into `zu_stop`.
- Family: 3. Siblings checked: data frame columns and NDJSON give the same failures.
- Test the suite lacked: every recognised class crossed with every storage type, under `outcome()`.
- Found by hunters 1 and 3.

## 5. Seed the data frame key index so colliding keys cannot make it quadratic — #44, medium, reproduced
- Where: [zu_parse.c:410-419](https://github.com/pedrobtz/zujson/blob/825f259/src/zu_parse.c#L410-L419), the probes at `:482-512`, `zu_tick` at `:230`
- Trigger: one record with 2^15 keys colliding in the low 24 bits of FNV-1a (2.1 MB) takes 5.7 s against 0.014 s for a control. SIGINT is honoured only at the end.
- Cause: an unseeded hash with a power-of-two mask.
- Fix: a per-call seed or a keyed hash; tick inside the probe loop.
- Family: none (see Cross-cutting).
- Test the suite lacked: a timing differential between a colliding body and a control.

## 6. Make max_df_cells bound the whole body, not each frame — #45, medium, reproduced
- Where: [zu_parse.c:400-408](https://github.com/pedrobtz/zujson/blob/825f259/src/zu_parse.c#L400-L408); `df` is passed unchanged at `:341`, `:688` and `:917`
- Trigger: 40 frames of 2,000 records in an 836 KB body build 1.6e8 cells under the 5e7 default. Under a budget of 4, two 2x2 frames are accepted.
- Fix: one remaining-budget counter per call, or document per frame.
- Family: 3.
- Test the suite lacked: two frames, each under the budget and together over it.

## 7. Parse integers wider than uint64 to the nearest double — #46, medium, reproduced
- Where: [zu_parse.c:79-81](https://github.com/pedrobtz/zujson/blob/825f259/src/zu_parse.c#L79-L81)
- Trigger: `7908650058519908757503158852011` and the same digits with `.0` parse to doubles 1 ulp apart. The 309-digit integer just below the midpoint gives `Inf`.
- Cause: `R_strtod` is not correctly rounded, and `BIGNUM_AS_RAW` sends it every integer past uint64.
- Fix: yyjson's correctly rounded reader for finite big integers; reconcile §5's two promises.
- Family: 4.
- Test the suite lacked: a differential against `.0` spellings and against a reference.

## 8. Build NDJSON bodies in C so a large body is a zujson_write_error and _raw skips the string — #47, medium, reproduced
- Where: [R/ndjson.R:74](https://github.com/pedrobtz/zujson/blob/825f259/R/ndjson.R#L74), [:83-89](https://github.com/pedrobtz/zujson/blob/825f259/R/ndjson.R#L83-L89)
- Trigger: `json_write_ndjson(list(s, s, s, s))` with `s` of 6e8 bytes raises the bare `simpleError` "result would exceed 2^31-1 bytes". `_raw` does the same.
- Fix: join in C; build the raw output directly.
- Family: 3. The per-record guard exists, and the body has none.
- Test the suite lacked: include the joined body in the `INT_MAX` straddle (#37).

## 9. Write bit64 integer64 as integers instead of their double bit pattern — #48, medium, reproduced
- Where: [zu_write.c:185-205](https://github.com/pedrobtz/zujson/blob/825f259/src/zu_write.c#L185-L205)
- Trigger: `json_write(bit64::as.integer64(c(1, 2, 2^40)))` gives `[5e-324,1e-323,5.43230922487e-312]`.
- Cause: the documented class fallthrough, applied to a class whose double does not carry its value (§6's own POSIXlt reasoning).
- Family: 4.
- Found by hunter 1; hunter 3 listed it as a surprise.

## 10. Keep an empty JSON key stable through parse and write — #49, medium, reproduced

## 11. Open json_parse_file() paths in the native encoding — #50, medium, reproduced

## 12. Make simplify = "coerce" strings independent of OutDec, scipen and sibling values — #51, medium, reproduced
- Where: [zu_parse.c:251-270](https://github.com/pedrobtz/zujson/blob/825f259/src/zu_parse.c#L251-L270), `:591`
- Trigger: `[1.5,"a"]` gives `"1,5"` under `OutDec = ","`. `[100000,"a"]` gives `"100000"`, while `[100000,1.5,"a"]` gives `"1e+05"`.
- By design in part: the strings match `as.character()`. The sibling dependence contradicts `?json_parse`'s "R's own promotion".
- Family: correctness.md's R-layer rule.
- Found by hunters 1 and 2.

## 13. Create the external pointer before the native allocation it owns — #52, medium, reproduced by fault injection

- Family: 2.

## Cross-cutting

- **Classed values are trusted by class.** #40, #43, #48 and #58 share a root:
  the writer decides what a value is from `class()` alone. It then believes the
  storage type, the length and the meaning the class implies. Every one of the
  four bugs is a classed value whose storage does not carry what the class
  says.
- **The UTF-8 discipline stops at values.** `zu_mkchar()` and `zu_w_str()`
  hold the line for values and keys. The paths around them do not: the input
  string before yyjson sees it (#42), the file path (#50) and condition
  messages (#53). These are the three places a string crosses without going
  through either helper.
- **Late features got fewer guards.** Data frames, NDJSON and
  `BIGNUM_AS_RAW` were added late in the 0.1.0 roadmap. They account for #40,
  #44, #45, #46, #47, #54, #56 and #57: a guard the single-document path had,
  missing on the new path (family 3).
- **Candidate rules for correctness.md** (to propose in `pedrobtz/packages`;
  not edited here):
  - *Floating-point remainders.* Splitting a double into integer units with
    `x - floor(x / k) * k` can yield exactly `k`. Floor to an integer type
    first, or clamp. Test the values a tiny `eps` below each boundary. (#41)
  - *Adversarial cost.* A structure meant to keep cost linear on untrusted
    input (a hash index, a cache) needs a seed or a worst-case bound, and a
    timing differential against a control. "No crash" and "correct result"
    both pass while the cost goes quadratic. (#44)

## Held: what was probed and stood

- **Memory safety.** ASan+UBSan over every probe in hunters 2 and 3: zero
  reports. `gctorture2(1)` over the parse matrix (177 s) and over both
  writers. `leaks(1)` 0 bytes across every error class. RSS flat over
  hundreds of interleaved failing and succeeding calls. 42 SIGINTs during
  parses and writes, with the next call correct each time.
- **Numbers, write.** 205,687 doubles parsed back by Python's `json`: 0
  mismatches. ±2^63 straddled with no UBSan report. Integer and double
  storage give identical bytes.
- **Numbers, read.** Int32 edges alone, in arrays and in data frame columns;
  20,000 near-overflow reals against jsonlite (0 differences); `1e309` in
  every context; comma-decimal `LC_NUMERIC`.
- **Dates.** 300,934 days and 472,772 seconds across the full range against
  Python; 5,000 random Dates and 5,000 POSIXct against `format()`; both
  range ends straddled with fractions. The only failure is #41.
- **Strings.** Every BMP scalar plus 5,000 astral code points as values and
  keys; escapes; latin1, UTF-8 and native spellings in a UTF-8 locale; bytes
  and invalid UTF-8 refused.
- **Depth.** 999/1000/1001 in both directions, under every mode, through data
  frames, list cells, NDJSON, raw and file. Everything written at 1000 parses
  back. The only miss is #57, on the safe side.
- **`max_df_cells`.** 399/400/401; the hash-growth sizes 4n−1/4n for n up to
  1025; malformed values all give `zujson_arg_error`; the clamp at 2^52.
- **Equivalent routes.** String, raw, `json_parse_raw`, file and a one-line
  NDJSON agree across 3 modes × `data_frame`. A data frame and its list of
  rows write identically. `_raw` equals the string bytes. Pretty and compact
  parse the same. NDJSON equals `json_write()` per record.
- **Differential fuzz.** 20,000 mutated documents: string and raw agree on
  value and error class; validate agrees with parse; every error inherits
  `zujson_error`; parse→write→parse is stable except #49.
- **Hostile session.** `LC_ALL=C`, de_DE.ISO8859-1 and de_DE.UTF-8;
  `OutDec`, `scipen`, `digits`, `warn = 2`; non-UTC TZs. Writer numbers,
  dates, factor frames, parsed numbers and error messages are byte-identical.
  The exceptions are #42 and #51.
- **NDJSON framing.** LF, CRLF, CR CR LF, blank and whitespace lines, no final
  newline, line numbers to line 8641, two values on a line refused, a raw
  newline in a string refused.
- **Arguments.** Every exported argument given NA, NULL, length 0 and 2,
  wrong types: all `zujson_arg_error`.
- **Ownership on the success path.** Eager release leaves nothing readable; a
  finalizer after release is a no-op; a second release is guarded. PROTECT is
  balanced on every exit by reading and under gctorture.

## Not reached

- Strings and outputs past `INT_MAX` bytes, except the NDJSON join (#47):
  memory. This is assurance gap #37.
- Long vectors; a frame near the 5e7 default.
- Windows (paths, code pages, iconv); arm64; R before 4.3.
- A natural R allocation failure (#52 is by injection); yyjson's own
  allocation failure inside the build.

## Not reproduced, and by design

- **Not reproduced:** none. Every claim the hunters reported reproduced on
  the coordinator's re-run, except two not re-run: the injected leak (#52,
  which needs the patched copy) and the per-frame budget at 836 KB (re-run in
  its small form, two 2x2 frames under a budget of 4).
- **By design, not filed:**
  - `[]` → `logical(0)`; partial names → array (§6); `json_validate()`
    returning `TRUE` past the depth cap and for NUL escapes (CLAUDE.md);
    `simplify = "none"` ignoring `data_frame`.
  - `auto_unbox = FALSE` not boxing data frame cells.
  - Duplicate names written as duplicate keys; `-0` written as `0`;
    difftime losing its units; row names dropped.
  - `as.character()`-based coerce strings, in so far as they match
    `as.character()` (#51 files only the part that does not).
- **Surprises, not filed:**
  - `json_write_ndjson(list(a = 1, b = 2))` silently drops the names.
  - Errors deep in a large value name no row, record or column.
  - A data frame's row count comes from its first column, not `row.names`.
  - `zujson_info()` raises when the option is malformed.
